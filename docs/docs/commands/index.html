Commands

Command reference.

Syntax, options, aliases, and examples for every command exposed by Silo.

Overview

Run Silo from the project you want to work on. The command name selects a built-in operation; an unrecognized name can select a configured quick command.

silo runOpen a session or run a command. silo image buildBuild the workspace image. silo configInspect and manage configuration. silo containersInspect or delete Silo containers. silo stateInspect or delete managed state. silo <name>Run a configured shortcut.

Help and version

silo --help
silo <command> --help
silo help <command>
silo --version

The help generated by the installed binary is authoritative for that version of Silo.

Run sessions and commands

silo run

Session command
silo run [--isolated] [--cpus <count>] [--memory <size>] [--sudo] [-- <command>...]

Opens the shared container for the current project. With no command, Silo starts the configured interactive shell. Arguments after -- run as an exact command inside the workspace.

Options

--isolated
Use a new one-shot container that is removed when the session ends.
--cpus <count>
Override the configured positive CPU count for this invocation.
--memory <size>
Override the configured memory using Apple container syntax, such as 4G.
--sudo
Grant the built-in container's silo user passwordless sudo access for this invocation.
-- <command>...
Run the command and arguments inside the container instead of opening a shell.

Examples

silo run
silo run -- cargo test --workspace
silo run --isolated -- ./scripts/check.sh
silo run --cpus 8 --memory 12G -- cargo build
silo run --sudo -- apt-get update

The separator is required: use silo run -- cargo test, not silo run cargo test.

Like resource overrides, --sudo reconciles the shared container's creation settings. Concurrent sessions in that container also have sudo until a later run reconciles it back to the configured value.

Build the image

silo image build

Image command
silo image build

Builds silo:latest without cached layers. Silo uses its embedded Dockerfile unless image.dockerfile selects a project-specific file.

Silo starts Apple's container system when necessary, serializes concurrent Silo builds, clears its temporary builder, and prunes dangling images afterward. A configured Dockerfile uses its containing directory as the build context.

See image configuration for custom Dockerfiles, CPU, memory, and sudo settings.

Inspect and edit configuration

silo config without a subcommand behaves like silo config list.

silo config listAlias: ls
Print the merged effective TOML, including normalized bind, state, and forwarding defaults.
silo config edit
Open the active project configuration, or the global file when no project file exists.
silo config edit --global
Always open or create the global configuration.
silo config default
Print the bundled starter configuration without reading project or filesystem state.
silo config path
Print active files in precedence order, labeled as global or project configuration.
silo config check
Validate the effective schema, Dockerfile, storage compatibility, and cross-field rules.

Editing uses $VISUAL, then $EDITOR, then vi. Silo reloads and validates the effective configuration after the editor exits, and warns about unknown keys.

Common inspection flow

silo config path
silo config list
silo config check

See the configuration reference for the complete schema and merge behavior.

Manage containers

silo containers without a subcommand behaves like silo containers list.

silo containers listAlias: ls
List Silo-owned containers with their identity, lifecycle, state, project, image, and allocated resources.
silo containers delete <selector> [--force]Alias: rm
Stop and delete exactly one Silo container selected by ID, unique ID prefix, project path, or unique project basename.

Examples

silo containers
silo containers delete my-project
silo containers rm silo-a0b1c2 --force

Without --force, Silo refuses to terminate an active session or shared-session handoff. Container deletion does not remove managed state.

--force can terminate active shells, commands, or agents.

Manage persistent state

silo state without a subcommand behaves like silo state list.

silo state listAlias: ls
List every Silo-managed state directory with its stable ID, scope, logical name, project, and host path.
silo state delete <selector>Alias: rm
Permanently delete one unused state directory selected by ID, unique ID prefix, project, or logical name.

Silo refuses deletion when the identity or storage path is inconsistent, the target is not a real directory, or any container still references it. There is no force option.

State deletion removes durable data recursively and cannot be undone through Silo. List state first and use the stable ID when a name is ambiguous.

Quick commands

silo <name>

Configured shortcut
silo <name> [additional arguments...]

Look up name in the effective [quick] table, append the invocation arguments, and run the result through the normal shared lifecycle.

Configure and run

[quick]
test = ["cargo", "test"]
agent = ["codex", "--model", "gpt-5"]
silo test --workspace
# Runs cargo test --workspace

silo agent --full-auto
# Runs codex --model gpt-5 --full-auto

Quick names cannot begin with - or shadow built-in commands such as run, config, or help. Use silo run -- <command> when no shortcut exists.
