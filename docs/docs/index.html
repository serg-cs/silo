Get started.

Install the binary, build the workspace image, and open a shell in your project.

Requirements

An Apple silicon Mac running macOS 26 or later, with:

  • Apple container
  • Rust 1.91 or newer, with Cargo

Silo starts the container service when a command needs it.

Install

cargo install --git https://github.com/serg-cs/silo --locked
silo --version

Cargo installs the binary to ~/.cargo/bin. If the shell cannot find silo, open a new terminal and check that ~/.cargo/bin is on $PATH.

Build the image

silo image build

The first build takes a while. A zero exit status means the image is ready. The default image includes Codex, Claude Code, Node.js, and everyday command-line tools.

Run silo image build again after upgrading Silo. silo image update refreshes the tool layer on a base you already have. A project that sets image.dockerfile should be your current directory for the build. See images.

Open a workspace

cd ~/code/my-project
silo run

Silo mounts the project and opens a Linux shell. The working directory is /home/silo/ plus the directory name. Your files stay on the Mac, and exit brings you back.

Use -- to run one command instead of a shell:

silo run -- uname -s

silo start keeps the container running between commands. silo stop shuts it down.

Upgrade

cargo install --git https://github.com/serg-cs/silo --locked
silo image build

The rebuild keeps the image's entrypoint and helpers matched to the binary. A container that is already running keeps its old image until you stop it and start the workspace again.

Uninstall

cargo uninstall silo

That removes the binary. Images, containers, and saved state stay behind. Clear containers and state with silo containers and silo state before uninstalling if you want them gone. Where that state lives is described in state.
